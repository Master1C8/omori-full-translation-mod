# Исследование OMORI

## Идентичность

- Название: OMORI
- Поддерживаемые версии RPG Maker: `1.0.8` и `1.6.1`
- Steam AppID: `1150690`
- Исполняемый файл Windows: `OMORI.exe`
- Стратегия запуска: `electron-cdp`
- Целевые среды: Windows x86-64 и macOS 12+

Источник истины для этих значений: `src/games/omori/game.json`. Версия игры определяется через `Utils.RPGMAKER_VERSION`; неизвестная версия вызывает предупреждение, но не блокирует запуск.

## Технология

OMORI использует RPG Maker и отрисовывает диалоги через canvas. Поэтому обычного обхода HTML Text-узлов недостаточно. Адаптер ограничен `Window_Message`, `Window_NameBox` и `Window_ChoiceList`; `Bitmap` меняется только для шрифтовых fallback-цепочек и целевой RTL-отрисовки уже переведённых реплик.

Лаунчер запускает игру с локальным debugging port и внедряет автономный bundle через Chrome DevTools Protocol. Файлы игры и сохранения не изменяются.

## Границы перевода

- В Story/Full DOM-runtime применяет готовый кэш только к видимым и изменённым текстовым блокам; в Screen автоматический DOM-проход отключён.
- В `Story Translation` canvas-адаптер ищет строку в кэше только для реплики, имени говорящего или варианта ответа. В `Full Translation` отдельный общий хук дополнительно обрабатывает целые строки недиалоговых `Window_Base`-окон. В `Screen Translation` тот же хук запоминает точные строки видимых активных окон для явной кнопки; при включённой автоматической опции `Window_Message.onEndOfText` отдельно отдаёт только завершившуюся страницу реплики.
- Полный набор `.HERO` расшифровывается отдельной явной операцией `Bulk Translate All Assets`.
- Автоматическое применение готового кэша Story/Full не обращается к сетевому провайдеру.
- Онлайн-провайдер получает массовый набор сразу после нажатия `Bulk Translate All Assets`.
- `Original` переводит runtime в режим `source`; последующие canvas-отрисовки используют исходный текст.
- Промах кэша оставляет исходную строку на английском и не запускает перевод в фоне.
- В стабильном `Story Translation` весь системный интерфейс намеренно исключён; из командных окон остаётся только `Window_ChoiceList`, потому что оно содержит варианты ответа внутри разговора.
- Экспериментальный `Full Translation` применяет готовый кэш к тексту `Window_Base`-окон — меню, `SAVE/LOAD`, подтверждениям, экипировке, навыкам, параметрам и описаниям — но не перехватывает изображения, поля ввода, технические элементы и отдельные sprite-bitmap без владельца-окна. Динамически собранная строка без точного ключа кэша тоже остаётся английской.
- `Screen Translation` не читает `.HERO`: `Translate current screen` переводит только DOM- и canvas-строки, видимые в момент нажатия. Отключаемая автоматическая опция запускает тот же runtime-путь только после завершения страницы диалога и не захватывает меню. Шаблоны сообщений разрешают динамические `\\V`/`\\N`/`\\P`/`\\G`, сохраняя остальные команды дословно, поэтому провайдер получает фактические значения переменных без потери разметки. Новая перерисовка снимает одобрение.

## Хранение и сеть

- настройки и положение панели: `localStorage` origin игры;
- кэш переводов: IndexedDB origin игры;
- Gemini API key: Keychain или Credential Manager, отдельно для `omori`;
- Google, Gemini и удалённые OpenAI-compatible профили получают извлечённые строки `.HERO` только во время явно запущенного Bulk либо точные видимые строки во время Screen-прохода;
- LM Studio и OpenAI-compatible loopback-профили обрабатывают текст на этом компьютере через авторизованный local helper;
- прежние данные удалённых провайдеров не читаются при запуске и удаляются только через явный `Reset all data`.

## Непроверенные сценарии

- полный запуск на настоящем Windows 10/11;
- запуск универсальной сборки на Apple Silicon и Intel Mac;
- длинная сюжетная сцена, бой, выборы и все варианты меню OMORI отдельно в Story, Full и Screen;
- повторное нажатие `Translate current screen` после изменения игровых переменных, а также отсутствие запросов между нажатиями;
- визуальные переполнения и выравнивание длинных переводов в узких Full-окнах;
- визуальная проверка RTL, CJK и длинных подписей внутри canvas;
- живой Gemini-запрос с пользовательским ключом;
- совместимость с будущими версиями OMORI.
