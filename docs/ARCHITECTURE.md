# Архитектура

```text
game.json
  → единожды задаёт имя продукта, Steam AppID, процесс, пути, target matchers и launchStrategy
OMORI Translator.app / OMORI Translator.exe
  → запускает локальный сервис offline/Gemini/OpenAI-compatible на случайном порту 127.0.0.1
  → запускает Steam AppID 1150690 нативно или в бутылке CrossOver
  → Electron открывает локальный debugging port на 127.0.0.1
  → универсальный нативный контроллер подключается только к странице, совпавшей с target matchers
  → translator.bundle.js = core + languages + providers + runtime helpers/panel + generated game config + OMORI adapter + runtime
  → адаптер задаёт DOM-правила, runtime создаёт изолированную панель в Shadow DOM
  → Bulk Translate читает атомарный asset index или расшифровывает изменившиеся .HERO рядом с выбранной копией игры
  → Google, Gemini, Argos, CTranslate2 + OPUS-MT, LM Studio или OpenAI-compatible API → постоянный кэш по языку/провайдеру/endpoint/модели
  → кнопка/хоткей и canvas-хуки только применяют готовый кэш к видимым узлам без сетевых запросов
  → MutationObserver регистрирует изменённые блоки, а IntersectionObserver запускает перевод только при их появлении возле экрана
```

Перевод и показ перевода — разные стадии:

1. `Bulk Translate All Assets` получает поддерживаемый текст из отдельного постоянного asset index, выполняет массовый перевод и записывает индивидуальные пары «исходник → перевод» в IndexedDB. При первом запуске, повреждении индекса либо изменении состава, размера или `mtime_ns` `.HERO` helper заново расшифровывает файлы и атомарно заменяет индекс. Индекс привязан к каноническому каталогу выбранной копии игры; частичный результат с ошибками чтения не сохраняется.
2. Во время игры DOM- и canvas-хуки не вызывают ни сетевые, ни локальные движки перевода. Они нормализуют фактически показанную исходную строку, ищут совпадение в RAM/IndexedDB и перерисовывают элемент готовым переводом. При промахе кэша остаётся исходный английский текст.

Режимы перевода имеют отдельную архитектурную границу. Стабильный `Story Translation` разрешает адаптеру работать только с поверхностями диалога: репликами, именами и вариантами ответа. Экспериментальный `Full Translation` хранится отдельным `translationScope` и не расширяет dialogue matchers. Он сопоставляет `Bitmap contents → Window_Base owner`, перехватывает целую строку в `drawText`/`drawTextEx` только для недиалоговых окон и читает перевод через тот же cache-only API runtime. Внутренний флаг запрещает повторный перевод посимвольной отрисовки `drawTextEx`, а `Window_Message`, `Window_NameBox` и `Window_ChoiceList` остаются на проверенных специализированных хуках. Смена Full/Story или Translation/Original обходит активное дерево окон и вызывает безопасный `refresh`, поэтому меню восстанавливается без перезапуска. Отдельные sprite-bitmap без `Window_Base` owner намеренно не перехватываются.

Титульный экран `Scene_OmoriTitleScreen` является сознательным исключением из canvas-подстановки: команды и подсказки остаются оригинальными, чтобы сохранить штатную типографику и избежать обрезания длинных переводов. Остальные сцены продолжают использовать локальный кэш.

Архитектура разделена на четыре слоя:

- `src/translation-core.js`, `src/languages.js`, `src/providers.js`, `src/runtime-ui.js`, `src/runtime-progress.js`, `src/runtime-panel.js`, `src/translator-runtime.js`, `src/argos_service.py` и `src/service_router.py` — общее ядро VN Revival; `runtime-ui` централизует рабочие/заблокированные состояния элементов управления, `runtime-progress` изолирует подсчёт защищённых слов, ETA и cooldown-текст, а `runtime-panel` содержит только Shadow DOM-разметку и CSS. Эти браузерные модули загружаются до основного runtime;
- `src/games/<game-id>/game.json` — идентичность, язык источника, проверенные версии, ресурсы, данные сборки и запуска конкретной игры;
- `src/games/<game-id>/adapter.js` — правила игрового DOM, canvas и API отрисовки;
- `src/games/<game-id>/tests/` — обязательные проверки конкретного адаптера;
- `src/controller/main.swift` и платформенные лаунчеры — универсальное внедрение, получающее идентичность игры из манифеста.

Сборщик проверяет схему и безопасные пути манифеста, генерирует из него браузерную конфигурацию, а затем включает DOM-адаптер перед runtime. В адаптере больше нет копий названия, `id`, языка и namespace. Детальный контракт находится в `docs/ADAPTER_CONTRACT.md`.

Для локального цикла `docs/DEV_MAP.md` связывает каждую область с минимальным набором исходников и тестов. `scripts/test-runtime.sh` и `scripts/test-service.sh` дают краткие адресные проверки; полный `scripts/test-omori.sh` остаётся обязательной межслойной и релизной проверкой. Корневой `AGENTS.md` хранит только инварианты и границы модулей, поэтому handoff-промт не повторяет README, changelog и QA-отчёт.

`launchStrategy` отделяет технологию запуска от DOM-адаптера. Сейчас реализована стратегия `electron-cdp`; неизвестное значение останавливает сборку. Это оставляет явную точку расширения для другой технологии новелл без ложного запуска через Electron.

Интерфейсный язык отделён от языка перевода: панель, настройки, статусы Gemini/Argos и системные предупреждения всегда формируются на английском. Поле `Language` влияет только на целевой язык игрового текста. Автоматическая проверка сборки не допускает кириллицу в интерфейсных исходниках и в инструкции Windows.

Каждый переведённый игровой блок получает нормализованный BCP 47-атрибут `lang`. Для RTL дополнительно применяются `dir="rtl"`, `direction: rtl`, `unicode-bidi: plaintext` и `text-align: start`; для CJK — правила строкового разбиения, для высоких письменностей — безопасная высота строки. Исходный шрифт игры дополняется цепочкой системных и Noto-шрифтов для выбранной письменности. Кнопкам разрешено увеличиваться и переносить длинный текст. Перед изменением все затронутые атрибуты и inline-стили сохраняются и затем восстанавливаются при `Original`, смене языка или сбросе.

`src/providers.js` определяет контракт переводчика: идентификатор, название, параллелизм, задержку, поддержку языков, разбиение и перевод одного фрагмента. Панель строит список сервисов из реестра. Google, Gemini, LM Studio и OpenAI-compatible AI используют полный каталог языковых кодов, но игровая разметка отделяется до вызова любого провайдера. Gemini работает последовательно через `gemini-2.5-flash-lite`, использует структурированный JSON-ответ и возвращает ошибки ключа, квоты и блокировки отдельными кодами. LM Studio и общий OpenAI-compatible provider также работают последовательно и делегируют генерацию выбранной модели локальному helper. Argos и CTranslate2 сообщают собственные каталоги, поэтому панель показывает только их English → target варианты. Исходный язык текущего контракта фиксирован как английский. Argos provider имеет concurrency `1` и вызывает проверенный одиночный `/v1/translate`: измерения живого журнала показали регрессию throughput при группировке строк с неизменным beam size `4`.

Перед единым provider contract работает лексический слой `translation-core.js`. Он сканирует строку слева направо и выделяет точные токены: длинные RPG Maker-команды с `[]`/`<>`, фактические безаргументные команды полного английского корпуса (`\itemget`, `\LECLEAR`, `\OOOO`, `\spxh`, `\sxbf`, `\shaw` и speaker-коды, включая `\art`/`\ber`), односимвольные escapes включая `\"`, `<...>`, `[...]` и `VRCTXSEP<n>X`. Для всех провайдеров действует один сегментный конвейер: ни один защищённый токен не отправляется модели, переводятся только непустые английские `text`-сегменты, после чего они сшиваются с побайтно исходным skeleton.

Сегментная сборка сохраняет исходные пробелы вокруг жёстких flow-кодов (`\!`, `\.`, `\|`, `\^`, `\{`, `\}`, `\\`), `<br>`, prefix- и terminal-команд. Пунктуация непосредственно после flow-кода и placeholder-символы также становятся локальными токенами. Слабая модель поэтому физически не может изменить или переставить служебную разметку. Финальная layout-проверка выполняется до IndexedDB и повторно при чтении RAM/fuzzy cache; придуманная моделью команда отклоняется как `markup_format_invalid`.

До обращения к провайдеру runtime удаляет из Bulk строки без переводимого текста, font coverage и Base64-содержимое ROBOHEART. ALL CAPS локально нормализуется для модели и возвращается к исходному display-case после ответа. Общая quality-проверка требует сохранения числовых и валютных литералов, отклоняет очевидную потерю предложений и аномальное разрастание/повторение результата. Ошибка `translation_quality_invalid` не создаёт cache entry; исходная строка остаётся доступной для повторного прохода или другого провайдера.

Защита имеет identity `omori-markup-v3`, включённую в provider variant cache key. IndexedDB schema 5 очищает несовместимый provider-store `translations`, но сохраняет отдельный store `translationPackEntries` schema 4 со всеми импортированными packs. Модели локальных движков, сохранения игры, настройки и credential vault находятся вне очищаемого provider-store и сохраняются.

IndexedDB остаётся полным постоянным кэшем без фиксированного лимита. RAM-кэш работает как LRU и удерживает не более 50 000 последних записей. Ключ v3 включает `game-id`, провайдера и язык. Ключ v4 дополнительно содержит fingerprint варианта провайдера; для LM Studio это идентификатор модели и версия prompt, а для OpenAI-compatible AI — preset, Base URL, модель и версия prompt. Число записей и байты ведутся в компактных метаданных `localStorage`. Перед каждой мутацией устанавливается dirty-маркер; RAM и метаданные меняются только после `transaction.oncomplete`, а error/abort возвращается вызывающей операции. Маркер снимается только после сохранения новых метаданных; при аварии или несовпадении `objectStore.count()` статистика восстанавливается потоковым курсором.

Чужой cache-файл импортируется как отдельный translation pack, а не сливается с provider store. Первый потоковый проход валидирует формат, `gameId`, каждый language/provider/model scope и точное расположение защищённой OMORI-разметки; до подтверждения запись не начинается. Модалка позволяет выбрать язык и, если файл смешанный, конкретный provider/model variant. Второй проход пишет новый случайный pack ID пакетами по 250 записей; метаданные делают его активным только после полного успешного прохода. Предыдущий pack остаётся активным до этой точки, поэтому ошибка не оставляет частично установленный перевод. Lookup сначала проверяет активный pack выбранного языка, затем собственный кэш текущего провайдера. Удаление pack возвращает собственный кэш без перезаписи или потери данных.

Во время Bulk и Test Phrase runtime добавляет каждый обработанный результат в живой журнал безопасными `textContent`-узлами; кэш-попадания получают видимую отметку `cache`. Поэтому повторный проход не выглядит зависшим до первого сетевого запроса. Обычное cache-only применение игрового текста в Story или Full логирование не включает. Живой контейнер автоматически раскрывается и обычно хранит 40 последних DOM-записей. Фиксатор `Stop scroll` отключает только автоследование: runtime сохраняет первую видимую запись и её viewport-смещение, удерживает 40 новейших строк плюс окно не более 40 строк вокруг якоря и обновляет якорь только после ручного wheel/pointer/touch/keyboard-scroll. `Resume scroll` сокращает DOM обратно до 40 записей и возвращает `scrollTop` к новым строкам; перевод и сохранение истории во время паузы не останавливаются. Runtime отправляет пары локальному helper, который под блокировкой лениво строит SHA-256-набор идентичности provider/language/source/translation и дополняет `translation-history.jsonl` только отсутствующими парами. Это позволяет восстановить историю из существующего кэша без неограниченных дублей. Авторизованные loopback endpoints возвращают до 500 последних записей (UI запрашивает 200) и потоково отдают полный JSONL для сохранения. `Clear view` и `Reset all data` не удаляют этот файл.

После фактического старта Bulk или Test Phrase runtime добавляет host-класс `bulkBusyHost` и растягивает Shadow DOM-панель на весь viewport. CSS скрывает все корневые секции, кроме строки прогресса и контейнера настроек; внутри контейнера остаются только растянутый журнал и строка с кнопкой именно активной операции. Заголовок, сворачивание, update status, настройки сервисов, кэш-инструменты и toolbar журнала недоступны до завершения. Счётчик слов строится только по `text`-сегментам `tokenizeProtectedMarkup`, поэтому команды OMORI не считаются словами. ETA использует скользящее окно только свежих переводов текущей операции (`newlyTranslated`/`created`): cache hit уменьшает потенциальный остаток, но не входит в числитель throughput. Пересчёт сглаживается и ставится на паузу во время запуска/установки локальной модели и cooldown провайдера; отображаемая доля при этом остаётся словарной. `finally` всегда снимает оба busy-класса и восстанавливает сохранённые состояния элементов управления.

Экспорт версии 2 — JSON Lines: одна строка заголовка и одна строка на запись. IndexedDB читается транзакциями по 250 элементов. При наличии File System Access API поток сразу направляется в выбранный файл; fallback создаёт `Blob` из `ReadableStream`, не удерживая массив объектов и его JSON-копию в JavaScript heap. Импорт JSONL сначала потоково валидирует весь файл, затем повторно читает его и записывает пакеты по 250 элементов, поэтому повреждённый файл не импортируется частично; прежний монолитный JSON версии 1 поддерживается для обратной совместимости.

При старте текстовые контейнеры регистрируются один раз. После этого `IntersectionObserver` сообщает только о блоках, приблизившихся к viewport, а `MutationObserver` добавляет изменённые React-узлы. Автопроход работает по этому ограниченному набору и не повторяет полный `TreeWalker` на каждой прокрутке. При `document.hidden` таймер останавливается и активный запрос отменяется. Для старых Chromium без `IntersectionObserver` сохранён совместимый, но менее экономный fallback по событию прокрутки.

Публичный сценарий сборки закреплён за одной игрой (`scripts/build-omori.sh`). Общий сборщик не имеет цели по умолчанию и требует явный `VNREVIVAL_GAME=<game-id>`, поэтому пропущенная переменная не может молча выпустить приложение с чужим адаптером. OMORI manifest указывает единый исходный `assets/icon-1024.png`, пиксельно эквивалентный игровому `app.nw/icon/icon.png`: macOS получает ICNS из `assets/AppIcon.icns`, Windows-сборщик создаёт из PNG ICO с размерами 16/24/32/48/64/128/256. Сборка macOS объединяет `arm64` и `x86_64` через `lipo`. По умолчанию применяется ad-hoc подпись; при наличии Developer ID и профиля `notarytool` включаются hardened runtime, временная метка, нотариальное заверение и stapling. Windows-сборка при наличии PFX и `osslsigncode` подписывает EXE Authenticode до упаковки.

Каталог `launcher/READY_TO_SHARE/` хранит готовые ZIP-релизы и не отслеживается Git. Сборщик создаёт и проверяет пару текущей версии — macOS и Windows — но не удаляет предыдущие готовые архивы. Распакованное macOS-приложение и служебные SHA-256 находятся в `.build/` и не смешиваются с файлами для пользователей.

Общее ядро не содержит идентичность конкретной игры. OMORI получает название, пути, matchers и ресурсы из `src/games/omori/game.json`; DOM- и canvas-правила находятся только в его адаптере.

Canvas-адаптер использует только cache-only API runtime: мгновенно проверяет `queryMemoryCache`, регистрирует промах через `registerAdapterText` и, если нужен прямой асинхронный поиск, вызывает `translateAdapterText`. Ни один из этих методов не обращается к провайдеру: поиск ограничен RAM/IndexedDB, а после попадания adapter callback перерисовывает открытые окна. Полный набор `.HERO` обрабатывается только явной кнопкой `Bulk Translate All Assets`; для онлайн-сервисов перед операцией требуется отдельное согласие.

Разбиение длинных запросов выполняется только по границам расширенных графем: мод не разделяет суррогатные пары, комбинируемые знаки, индийские слоги, emoji ZWJ или региональные пары флагов. Используется `Intl.Segmenter` с автономным Unicode-совместимым резервным алгоритмом.

Google имеет concurrency `1` и выдерживает 1 секунду между свежими запросами как в Bulk, так и в Test Phrase. Оба прохода используют общий rate-limit wrapper: `HTTP 429` сохраняет в `localStorage` срок cooldown и следующую ступень backoff, обновляет обратный отсчёт раз в секунду и повторяет текущий chunk внутри той же job. Поэтому `done` и `failed` во время ожидаемой паузы не растут, а повторные ограничения увеличивают паузу с 15 до 30 и 60 минут даже при перезапуске приложения; успешный свежий запрос очищает состояние. Состояние старого формата с одним deadline автоматически читается и переводится на новую схему.

Соседние текстовые узлы одного логического блока остаются одной job и одним составным cache key с локальными разделителями `VRCTXSEP…X`. Разделители не отправляются модели: каждый текстовый фрагмент переводится через общий сегментный конвейер, затем ответ собирается и разбирается обратно по исходным узлам, поэтому теги и обработчики DOM не заменяются.

`src/argos_service.py` — общий локальный HTTP-мост. Он слушает только `127.0.0.1`, защищён одноразовым ключом запуска и предоставляет Argos, CTranslate2, Gemini, LM Studio, OpenAI-compatible AI и служебные команды лаунчера. Общий provider имеет профили OpenCode Go, OpenRouter, DeepSeek, LM Studio и Custom, читает `/models` и вызывает `/chat/completions`. Удалённый Custom URL обязан использовать HTTPS, локальный HTTP ограничен loopback; API-ключ хранится в системном credential vault отдельно по Base URL. Ответ AI-провайдеров запрашивается по JSON Schema с текстовым fallback; prompt описывает только качество перевода, потому что общий runtime заранее удаляет игровую разметку. Для Argos мост устанавливает фиксированную версию движка только из бинарных пакетов, потоково скачивает прямые модели English → target и ограничивает размер входных данных. Служебный batch endpoint остаётся покрыт unit-тестом, но штатный provider его не использует после измеренной регрессии. CPU/INT8 сохраняются, `interThreads=1`, `intraThreads` ограничен четырьмя, CTranslate2 batch size равен `32`. Beam size берётся из стандартных настроек Argos (сейчас `4`) и не меняется. Используется встроенное разбиение английских предложений без Torch, spaCy, Stanza и ONNX.

POST-маршруты локального моста описаны декларативно в отдельном `src/service_router.py`: `ArgosPostRouter` связывает неизменные URL с методами bridge и именами входных полей, а подтверждения удаления ключей/смены executable и семантика журналов проверяются до вызова сервисов. `ArgosRequestHandler` отвечает только за авторизацию, JSON-обрамление и преобразование ошибок в HTTP-ответы. Сборщики macOS и Windows всегда кладут router рядом с `argos_service.py`, поэтому Python embeddable и системный runtime импортируют один и тот же код.

При старте runtime один раз вызывает авторизованный `/v1/update/check`. Helper с 10-секундным тайм-аутом получает только фиксированный HTTPS URL `https://vnrevival.fun/downloads/omori/latest.json`, запрещает смену host при redirect, ограничивает ответ 64 KiB и валидирует `schemaVersion`, `product`, SemVer-подобную версию, `cacheCompatibility` (`keep`/`rebuild`), положительный `cacheSchema` и до пяти непустых строк `changes` длиной не более 200 символов. Runtime дополнительно ограничивает всю операцию 12 секундами, сравнивает три числовых компонента версии и выводит результат в отдельный DOM-узел. Для доступного релиза безопасными `textContent`-элементами показываются первые три изменения; пустой список заменяется встроенной заглушкой до подключения реального источника описаний. Сбой проверки не влияет на запуск и не скрывается общим статусом Bulk. Контракт манифеста:

```json
{"schemaVersion":1,"product":"omori-translator","version":"0.9.44","cacheCompatibility":"keep","cacheSchema":3,"changes":["Placeholder improvement","Placeholder bug fix"]}
```

CTranslate2 + OPUS-MT использует тот же минимальный Python runtime, но отдельный каталог моделей. На macOS runtime устанавливается только из точных binary wheels hash-locked манифеста с `--require-hashes --no-deps`; NW.js 0.115.0 также проверяется официальным SHA-256 до распаковки. Helper получает последнюю официальную прямую модель из README Helsinki-NLP, ограниченно и безопасно распаковывает ZIP, преобразует Marian/OPUS-модель через `OpusMTConverter` в INT8 и сохраняет SentencePiece tokenizers. Перевод выполняется на CPU одним запросом и не более чем четырьмя вычислительными потоками. Исходный ZIP и staging удаляются; готовая модель удаляется только явной кнопкой `Remove model`.

Для Argos и CTranslate2 ветка `Test Phrase · All Languages` сначала получает каталог от helper, затем для каждого языка без готовой тестовой записи проверяет соответствующий status endpoint, при необходимости подготавливает runtime и устанавливает модель. Только подтверждённая пользователем тестовая операция инициирует эти загрузки; обычное применение кэша не устанавливает модели и не обращается к сети. Все шаги выполняются последовательно, а установленные модели сохраняются для последующих запусков.

Gemini API key поступает в локальный мост один раз при сохранении, после чего поле панели очищается. На macOS ключ хранится в Keychain, на Windows — в Credential Manager под `game-id`; JavaScript игры не получает сохранённый секрет обратно. Запрос к Gemini отправляется локальным мостом по HTTPS с ключом в заголовке, а не в URL. Для регулируемых категорий безопасности передаётся `OFF`, однако обязательные ограничения Google остаются. Ответ запрашивается по JSON-схеме, проверяется и только затем возвращается runtime.

Windows-лаунчер `launcher/windows/launcher.c` — нативное x86-64 Win32-приложение без консольного окна и прав администратора. Оно находит игру во всех Steam-библиотеках, запускает комплектный локальный Python-сервис, подключается к Electron через WinHTTP WebSocket и держит сервис живым до закрытия игры. В Windows ZIP входят официальный embeddable Python и минимальный Argos/CTranslate2 runtime; языковые модели остаются отдельными загрузками.

Если автоматический поиск не находит игру, Windows показывает стандартный диалог `.exe` и сохраняет путь в `HKCU`; macOS показывает системный выбор файла и сохраняет путь в Application Support по `game-id`. Сохранённый путь проверяется при каждом старте, после его исчезновения поиск и запрос повторяются. Имя `.exe` из манифеста по-прежнему используется для автоматического поиска.

На macOS одной проверки существования `.app` недостаточно: Steam может создать на рабочем столе одноимённый ярлык, который лишь выполняет `open steam://run/<AppID>`. Лаунчер нормализует завершающий `/`, принимает native app только при наличии `Contents/Resources/app.nw` и исполняемого файла в `Contents/MacOS`, игнорирует невалидный сохранённый путь и записывает найденный канонический путь Steam обратно в настройки.

Язык, провайдер и `translationScope` (`story`/`full`) сохраняются сразу при изменении соответствующего элемента панели. Автоприменение кэша всегда включено и не имеет отдельного элемента управления. Настройки постоянно видимы в развёрнутом состоянии, а режим исходника/перевода представлен сегментированным toggle. Положение панели сохраняется; каждый новый runtime стартует развёрнутым. Единственная кнопка заголовка переключает полную панель и один `+`. Drag использует pointer capture, глобальные pointer-события и mouse fallback для старых NW.js; в свёрнутом состоянии сам плюсик одновременно служит областью перетаскивания. Движение задаётся через `translate3d` от фактического `getBoundingClientRect()`, чтобы не зависеть от масштабирования игрового контейнера.

Долгие кнопочные операции используют общий CSS-индикатор `working`. Для `Reset all data` индикатор включается после подтверждения и до завершения асинхронной очистки IndexedDB; сама кнопка на это время блокируется, а ошибка выводится в общей строке статуса.

После внедрения Windows-лаунчер хранит дескриптор именно запущенного экземпляра игры, сверяет полный путь исполняемого файла и выбранную CDP-страницу. При ошибке запуска или внедрения cleanup останавливает только экземпляр, созданный этим запуском; после успешной инъекции игра остаётся жить независимо от лаунчера. CDP-ответы разбираются структурным ограниченным JSON-сканером с точным сопоставлением числового `id`.

Размер комплектного Windows-движка Argos — около 110 МБ без языковых моделей. Установленная модель English → Russian занимает около 207 МБ. При тесте Windows x64-сборки через CrossOver/Rosetta первая загрузка движка заняла 52 секунды, последующие проверки — около 0,14 секунды.

Мод принципиально не заменяет `innerHTML`: это сохраняет теги, обработчики кликов и структуру React. Стилизованный абзац остаётся одной job, но общий защищённый конвейер переводит его текстовые фрагменты отдельно и возвращает собранный результат в существующие текстовые узлы.
