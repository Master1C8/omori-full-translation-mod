# Архитектура

```text
game.json
  → единожды задаёт имя продукта, Steam AppID, процесс, пути, target matchers и launchStrategy
OMORI Translator.app / OMORI Translator.exe
  → запускает локальный сервис offline/Gemini/OpenAI-compatible на случайном порту 127.0.0.1
  → запускает Steam AppID 1150690 нативно или в бутылке CrossOver
  → Electron открывает локальный debugging port на 127.0.0.1
  → универсальный нативный контроллер подключается только к странице, совпавшей с target matchers
  → translator.bundle.js = core + languages + providers + generated game config + OMORI adapter + runtime
  → адаптер задаёт DOM-правила, runtime создаёт изолированную панель в Shadow DOM
  → Bulk Translate читает атомарный asset index или расшифровывает изменившиеся .HERO рядом с выбранной копией игры
  → Super Bulk последовательно повторяет этот проход для фиксированных 17 языков
  → Google, Gemini, MyMemory, Argos, Bergamot, CTranslate2 + OPUS-MT, LM Studio или OpenAI-compatible API → постоянный кэш по языку/провайдеру/endpoint/модели
  → кнопка/хоткей и canvas-хуки только применяют готовый кэш к видимым узлам без сетевых запросов
  → MutationObserver регистрирует изменённые блоки, а IntersectionObserver запускает перевод только при их появлении возле экрана
```

Перевод и показ перевода — разные стадии:

1. `Bulk Translate All Assets` получает поддерживаемый текст из отдельного постоянного asset index, выполняет массовый перевод и записывает индивидуальные пары «исходник → перевод» в IndexedDB. При первом запуске, повреждении индекса либо изменении состава, размера или `mtime_ns` `.HERO` helper заново расшифровывает файлы и атомарно заменяет индекс. Индекс привязан к каноническому каталогу выбранной копии игры; частичный результат с ошибками чтения не сохраняется.
2. `Super Bulk Translation` извлекает набор один раз и строго последовательно вызывает тот же worker для `es`, `de`, `pl`, `vi`, `ru`, `ar`, `fa`, `iw`, `zh-CN`, `zh-TW`, `ja`, `ko`, `hi`, `bn`, `th`, `my`, `ka`. Каждый язык имеет отдельный namespace кэша, поэтому повторный запуск пропускает готовые записи.
3. Во время игры DOM- и canvas-хуки не вызывают ни сетевые, ни локальные движки перевода. Они нормализуют фактически показанную исходную строку, ищут совпадение в RAM/IndexedDB и перерисовывают элемент готовым переводом. При промахе кэша остаётся исходный английский текст.

Титульный экран `Scene_OmoriTitleScreen` является сознательным исключением из canvas-подстановки: команды и подсказки остаются оригинальными, чтобы сохранить штатную типографику и избежать обрезания длинных переводов. Остальные сцены продолжают использовать локальный кэш.

Архитектура разделена на четыре слоя:

- `src/translation-core.js`, `src/languages.js`, `src/providers.js`, `src/translator-runtime.js` и `src/argos_service.py` — общее ядро VN Revival;
- `src/games/<game-id>/game.json` — идентичность, язык источника, проверенные версии, ресурсы, данные сборки и запуска конкретной игры;
- `src/games/<game-id>/adapter.js` — правила игрового DOM, canvas и API отрисовки;
- `src/games/<game-id>/tests/` — обязательные проверки конкретного адаптера;
- `src/controller/main.swift` и платформенные лаунчеры — универсальное внедрение, получающее идентичность игры из манифеста.

Сборщик проверяет схему и безопасные пути манифеста, генерирует из него браузерную конфигурацию, а затем включает DOM-адаптер перед runtime. В адаптере больше нет копий названия, `id`, языка и namespace. Детальный контракт находится в `docs/ADAPTER_CONTRACT.md`.

`launchStrategy` отделяет технологию запуска от DOM-адаптера. Сейчас реализована стратегия `electron-cdp`; неизвестное значение останавливает сборку. Это оставляет явную точку расширения для другой технологии новелл без ложного запуска через Electron.

Интерфейсный язык отделён от языка перевода: панель, настройки, статусы Gemini/Argos и системные предупреждения всегда формируются на английском. Поле `Language` влияет только на целевой язык игрового текста. Автоматическая проверка сборки не допускает кириллицу в интерфейсных исходниках и в инструкции Windows.

Каждый переведённый игровой блок получает нормализованный BCP 47-атрибут `lang`. Для RTL дополнительно применяются `dir="rtl"`, `direction: rtl`, `unicode-bidi: plaintext` и `text-align: start`; для CJK — правила строкового разбиения, для высоких письменностей — безопасная высота строки. Исходный шрифт игры дополняется цепочкой системных и Noto-шрифтов для выбранной письменности. Кнопкам разрешено увеличиваться и переносить длинный текст. Перед изменением все затронутые атрибуты и inline-стили сохраняются и затем восстанавливаются при `Original`, смене языка или сбросе.

`src/providers.js` определяет контракт переводчика: идентификатор, название, параллелизм, задержку, поддержку языков, разбиение и перевод одного фрагмента. Панель строит список сервисов из реестра. Google, Gemini, LM Studio и OpenAI-compatible AI используют полный каталог языковых кодов, но игровая разметка отделяется до вызова любого провайдера. Gemini работает последовательно через `gemini-2.5-flash-lite`, использует структурированный JSON-ответ и возвращает ошибки ключа, квоты и блокировки отдельными кодами. LM Studio и общий OpenAI-compatible provider также работают последовательно и делегируют генерацию выбранной модели локальному helper. Для MyMemory устаревшие и поставщико-зависимые коды нормализуются (`iw` → `he`, `jw` → `jv`, `tl` → `fil`), но наличие машинного перевода для каждой пары заранее не заявляется. Argos, Bergamot и CTranslate2 сообщают собственные каталоги, поэтому панель показывает только их English → target варианты. Исходный язык текущего контракта фиксирован как английский. Argos provider имеет concurrency `1` и вызывает проверенный одиночный `/v1/translate`: измерения живого журнала показали регрессию throughput при группировке строк с неизменным beam size `4`.

Перед единым provider contract работает лексический слой `translation-core.js`. Он сканирует строку слева направо и выделяет точные токены: длинные RPG Maker-команды с `[]`/`<>`, фактические безаргументные команды полного английского корпуса (`\itemget`, `\LECLEAR`, `\OOOO`, `\spxh`, `\sxbf`, `\shaw` и speaker-коды), односимвольные escapes включая `\"`, `<...>`, `[...]` и `VRCTXSEP<n>X`. Оптимистичный проход заменяет токены уникальными ASCII-маркерами, переводит всю фразу для сохранения контекста, требует каждый маркер ровно один раз и в исходном порядке, затем возвращает побайтно исходные токены.

После восстановления layout repair возвращает исходное соседство пробелов для жёстких flow-кодов (`\!`, `\.`, `\|`, `\^`, `\{`, `\}`, `\\`) и `<br>`, а также для последовательностей команд до первого текста и после последнего текста. Поэтому добавленный Google пробел не превращается в видимый отступ. Цветовые, переменные и input-icon команды внутри предложения могут перемещаться вместе с русским порядком слов. Если текст оказался перед исходной prefix-командой или после terminal-команды, оптимистичный ответ отклоняется и fallback переводит только `text`-сегменты, сшивая их с оригинальным skeleton. Финальная layout-проверка выполняется до IndexedDB и повторно при чтении RAM/fuzzy cache.

Защита имеет identity `omori-markup-v2`, включённую в provider variant cache key. IndexedDB поднята до версии 3: upgrade очищает прежний translation object store, а метаданные перенесены на `cache-meta.v3`. Миграция намеренно затрагивает только расходуемый кэш переводов; модели локальных движков, сохранения игры, credential vault и `translation-history.jsonl` находятся вне этой базы и сохраняются.

IndexedDB остаётся полным постоянным кэшем без фиксированного лимита. RAM-кэш работает как LRU и удерживает не более 50 000 последних записей. Ключ v3 включает `game-id`, провайдера и язык. Ключ v4 дополнительно содержит fingerprint варианта провайдера; для LM Studio это идентификатор модели и версия prompt, а для OpenAI-compatible AI — preset, Base URL, модель и версия prompt. Число записей и байты ведутся в компактных метаданных `localStorage`. Перед каждой мутацией устанавливается dirty-маркер, который снимается только после сохранения новых метаданных; при аварии или несовпадении `objectStore.count()` статистика восстанавливается потоковым курсором.

Во время Bulk, Super Bulk и Test Phrase runtime добавляет каждый обработанный результат в живой журнал безопасными `textContent`-узлами; кэш-попадания получают видимую отметку `cache`. Поэтому повторный проход не выглядит зависшим до первого сетевого запроса. Обычное cache-only применение реплик во время игры логирование не включает. Живой контейнер автоматически раскрывается и хранит не более 40 последних DOM-записей. Runtime отправляет пары локальному helper, который под блокировкой лениво строит SHA-256-набор идентичности provider/language/source/translation и дополняет `translation-history.jsonl` только отсутствующими парами. Это позволяет восстановить историю из существующего кэша без неограниченных дублей. Авторизованные loopback endpoints возвращают до 500 последних записей (UI запрашивает 200) и потоково отдают полный JSONL для сохранения. `Clear view` и `Reset all data` не удаляют этот файл.

После фактического старта любой из трёх переводческих операций runtime добавляет host-класс `bulkBusyHost` и растягивает Shadow DOM-панель на весь viewport. CSS скрывает все корневые секции, кроме строки прогресса и контейнера настроек; внутри контейнера остаются только растянутый журнал и строка с кнопкой именно активной операции. Заголовок, сворачивание, update status, настройки сервисов, кэш-инструменты и toolbar журнала недоступны до завершения. Счётчик слов строится только по `text`-сегментам `tokenizeProtectedMarkup`, поэтому команды OMORI не считаются словами. ETA использует скользящее окно скорости завершённых jobs, сглаживает пересчёт и ставится на паузу во время запуска/установки локальной модели и cooldown провайдера; отображаемая доля при этом остаётся словарной. `finally` всегда снимает оба busy-класса и восстанавливает сохранённые состояния элементов управления.

Экспорт версии 2 — JSON Lines: одна строка заголовка и одна строка на запись. IndexedDB читается транзакциями по 250 элементов. При наличии File System Access API поток сразу направляется в выбранный файл; fallback создаёт `Blob` из `ReadableStream`, не удерживая массив объектов и его JSON-копию в JavaScript heap. Импорт JSONL сначала потоково валидирует весь файл, затем повторно читает его и записывает пакеты по 250 элементов, поэтому повреждённый файл не импортируется частично; прежний монолитный JSON версии 1 поддерживается для обратной совместимости.

При старте текстовые контейнеры регистрируются один раз. После этого `IntersectionObserver` сообщает только о блоках, приблизившихся к viewport, а `MutationObserver` добавляет изменённые React-узлы. Автопроход работает по этому ограниченному набору и не повторяет полный `TreeWalker` на каждой прокрутке. При `document.hidden` таймер останавливается и активный запрос отменяется. Для старых Chromium без `IntersectionObserver` сохранён совместимый, но менее экономный fallback по событию прокрутки.

Публичный сценарий сборки закреплён за одной игрой (`scripts/build-omori.sh`). Общий сборщик не имеет цели по умолчанию и требует явный `VNREVIVAL_GAME=<game-id>`, поэтому пропущенная переменная не может молча выпустить приложение с чужим адаптером. OMORI manifest указывает единый исходный `assets/icon-1024.png`, пиксельно эквивалентный игровому `app.nw/icon/icon.png`: macOS получает ICNS из `assets/AppIcon.icns`, Windows-сборщик создаёт из PNG ICO с размерами 16/24/32/48/64/128/256. Сборка macOS объединяет `arm64` и `x86_64` через `lipo`. По умолчанию применяется ad-hoc подпись; при наличии Developer ID и профиля `notarytool` включаются hardened runtime, временная метка, нотариальное заверение и stapling. Windows-сборка при наличии PFX и `osslsigncode` подписывает EXE Authenticode до упаковки.

Каталог `launcher/READY_TO_SHARE/` хранит готовые ZIP-релизы и не отслеживается Git. Сборщик создаёт и проверяет пару текущей версии — macOS и Windows — но не удаляет предыдущие готовые архивы. Распакованное macOS-приложение и служебные SHA-256 находятся в `.build/` и не смешиваются с файлами для пользователей.

Общее ядро не содержит идентичность конкретной игры. OMORI получает название, пути, matchers и ресурсы из `src/games/omori/game.json`; DOM- и canvas-правила находятся только в его адаптере.

Canvas-адаптер использует только защищённый метод runtime `translateAdapterText`. Метод никогда не обращается к провайдеру: он ищет строку в RAM/IndexedDB и запрашивает перерисовку после попадания. Полный набор `.HERO` обрабатывается только явной кнопкой `Bulk Translate All Assets`; для онлайн-сервисов перед операцией требуется отдельное согласие.

Разбиение длинных запросов выполняется только по границам расширенных графем: мод не разделяет суррогатные пары, комбинируемые знаки, индийские слоги, emoji ZWJ или региональные пары флагов. Используется `Intl.Segmenter` с автономным Unicode-совместимым резервным алгоритмом.

Google имеет concurrency `1` и выдерживает 5 секунд между свежими запросами как в Bulk, так и в Test Phrase. Оба прохода используют общий rate-limit wrapper: `HTTP 429` сохраняет в `localStorage` срок cooldown и следующую ступень backoff, обновляет обратный отсчёт раз в секунду и повторяет текущий chunk внутри той же job. Поэтому `done` и `failed` во время ожидаемой паузы не растут, а повторные ограничения увеличивают паузу с 15 до 30 и 60 минут даже при перезапуске приложения; успешный свежий запрос очищает состояние. Состояние старого формата с одним deadline автоматически читается и переводится на новую схему.

Соседние текстовые узлы одного логического блока отправляются вместе с устойчивыми маркерами `VRCTXSEP…X`. Ответ разбирается обратно по исходным узлам, поэтому теги и обработчики DOM не заменяются. Если переводчик удалил или переставил маркеры недопустимым способом, мод автоматически повторяет перевод отдельных фрагментов.

`src/argos_service.py` — общий локальный HTTP-мост. Он слушает только `127.0.0.1`, защищён одноразовым ключом запуска и предоставляет Argos, Bergamot, CTranslate2, Gemini, LM Studio, OpenAI-compatible AI и служебные команды лаунчера. Общий provider имеет профили OpenCode Go, OpenRouter, DeepSeek, LM Studio и Custom, читает `/models` и вызывает `/chat/completions`. Удалённый Custom URL обязан использовать HTTPS, локальный HTTP ограничен loopback; API-ключ хранится в системном credential vault отдельно по Base URL. Ответ запрашивается по JSON Schema с текстовым fallback и принимается только после проверки RPG Maker-кодов и `VRCTXSEP`-маркеров. Для Argos мост устанавливает фиксированную версию движка только из бинарных пакетов, потоково скачивает прямые модели English → target и ограничивает размер входных данных. Служебный batch endpoint остаётся покрыт unit-тестом, но штатный provider его не использует после измеренной регрессии. CPU/INT8 сохраняются, `interThreads=1`, `intraThreads` ограничен четырьмя, CTranslate2 batch size равен `32`. Beam size берётся из стандартных настроек Argos (сейчас `4`) и не меняется. Используется встроенное разбиение английских предложений без Torch, spaCy, Stanza и ONNX.

При старте runtime один раз вызывает авторизованный `/v1/update/check`. Helper с 10-секундным тайм-аутом получает только фиксированный HTTPS URL `https://vnrevival.fun/downloads/omori/latest.json`, запрещает смену host при redirect, ограничивает ответ 64 KiB и валидирует `schemaVersion`, `product`, SemVer-подобную версию, `cacheCompatibility` (`keep`/`rebuild`), положительный `cacheSchema` и до пяти непустых строк `changes` длиной не более 200 символов. Runtime дополнительно ограничивает всю операцию 12 секундами, сравнивает три числовых компонента версии и выводит результат в отдельный DOM-узел. Для доступного релиза безопасными `textContent`-элементами показываются первые три изменения; пустой список заменяется встроенной заглушкой до подключения реального источника описаний. Сбой проверки не влияет на запуск и не скрывается общим статусом Bulk. Контракт манифеста:

```json
{"schemaVersion":1,"product":"omori-translator","version":"0.9.38","cacheCompatibility":"keep","cacheSchema":3,"changes":["Placeholder improvement","Placeholder bug fix"]}
```

Bergamot 0.4.9 поставляется как официальный `@browsermt/bergamot-translator` WebAssembly runtime. Авторизованный helper отдаёт его JavaScript/WASM-файлы и установленные модельные буферы; browser runtime создаёт из них локальные Blob worker/module и не обращается к внешним origin во время перевода. Семь tiny-моделей TranslateLocally закреплены HTTPS URL и SHA-256; tar-архивы проверяются, отклоняют traversal, ссылки и device entries, после чего атомарно устанавливаются отдельно от Argos.

CTranslate2 + OPUS-MT использует тот же минимальный Python runtime, но отдельный каталог моделей. Helper получает последнюю официальную прямую модель из README Helsinki-NLP, ограниченно и безопасно распаковывает ZIP, преобразует Marian/OPUS-модель через `OpusMTConverter` в INT8 и сохраняет SentencePiece tokenizers. Перевод выполняется на CPU одним запросом и не более чем четырьмя вычислительными потоками. Исходный ZIP и staging удаляются; готовая модель удаляется только явной кнопкой `Remove model`.

Для Argos, Bergamot и CTranslate2 ветка `Test Phrase · All Languages` сначала получает каталог от helper, затем для каждого языка без готовой тестовой записи проверяет соответствующий status endpoint, при необходимости подготавливает runtime и устанавливает модель. Только подтверждённая пользователем тестовая операция инициирует эти загрузки; обычное применение кэша не устанавливает модели и не обращается к сети. Все шаги выполняются последовательно, а установленные модели сохраняются для последующих запусков.

Gemini API key поступает в локальный мост один раз при сохранении, после чего поле панели очищается. На macOS ключ хранится в Keychain, на Windows — в Credential Manager под `game-id`; JavaScript игры не получает сохранённый секрет обратно. Запрос к Gemini отправляется локальным мостом по HTTPS с ключом в заголовке, а не в URL. Для регулируемых категорий безопасности передаётся `OFF`, однако обязательные ограничения Google остаются. Ответ запрашивается по JSON-схеме, проверяется и только затем возвращается runtime.

Windows-лаунчер `launcher/windows/launcher.c` — нативное x86-64 Win32-приложение без консольного окна и прав администратора. Оно находит игру во всех Steam-библиотеках, запускает комплектный локальный Python-сервис, подключается к Electron через WinHTTP WebSocket и держит сервис живым до закрытия игры. В Windows ZIP входят официальный embeddable Python, минимальный Argos/CTranslate2 runtime и Bergamot WASM; языковые модели остаются отдельными загрузками.

Если автоматический поиск не находит игру, Windows показывает стандартный диалог `.exe` и сохраняет путь в `HKCU`; macOS показывает системный выбор файла и сохраняет путь в Application Support по `game-id`. Сохранённый путь проверяется при каждом старте, после его исчезновения поиск и запрос повторяются. Имя `.exe` из манифеста по-прежнему используется для автоматического поиска.

На macOS одной проверки существования `.app` недостаточно: Steam может создать на рабочем столе одноимённый ярлык, который лишь выполняет `open steam://run/<AppID>`. Лаунчер нормализует завершающий `/`, принимает native app только при наличии `Contents/Resources/app.nw` и исполняемого файла в `Contents/MacOS`, игнорирует невалидный сохранённый путь и записывает найденный канонический путь Steam обратно в настройки.

Язык и провайдер сохраняются сразу при изменении соответствующего элемента панели. Автоприменение кэша всегда включено и не имеет отдельного элемента управления. Настройки постоянно видимы в развёрнутом состоянии, а режим исходника/перевода представлен сегментированным toggle. Положение панели сохраняется; каждый новый runtime стартует развёрнутым. Единственная кнопка заголовка переключает полную панель и один `+`. Drag использует pointer capture, глобальные pointer-события и mouse fallback для старых NW.js; в свёрнутом состоянии сам плюсик одновременно служит областью перетаскивания. Движение задаётся через `translate3d` от фактического `getBoundingClientRect()`, чтобы не зависеть от масштабирования игрового контейнера.

Долгие кнопочные операции используют общий CSS-индикатор `working`. Для `Reset all data` индикатор включается после подтверждения и до завершения асинхронной очистки IndexedDB; сама кнопка на это время блокируется, а ошибка выводится в общей строке статуса.

После внедрения Windows-лаунчер хранит дескриптор именно запущенного экземпляра игры, сверяет полный путь исполняемого файла и выбранную CDP-страницу. При ошибке запуска или внедрения cleanup останавливает только экземпляр, созданный этим запуском; после успешной инъекции игра остаётся жить независимо от лаунчера. CDP-ответы разбираются структурным ограниченным JSON-сканером с точным сопоставлением числового `id`.

Размер комплектного Windows-движка Argos — около 110 МБ без языковых моделей. Установленная модель English → Russian занимает около 207 МБ. При тесте Windows x64-сборки через CrossOver/Rosetta первая загрузка движка заняла 52 секунды, последующие проверки — около 0,14 секунды.

Мод принципиально не заменяет `innerHTML`: это сохраняет теги, обработчики кликов и структуру React. Стилизованный абзац переводится одним контекстным запросом, после чего результат возвращается в существующие текстовые узлы. Пофрагментные запросы используются только для одиночных узлов или как fallback при повреждении маркеров.
