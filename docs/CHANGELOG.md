# Changelog

## Версия 0.9.44 — 2026-08-28 — экспериментальный Full Translation

- Каталог приложения ограничен 30 языками, показанными на странице Stardew Valley VN Revival. Селектор, Bulk, импорт и Test Phrase используют один список; `ZH` сайта сопоставлен каноническому Google-коду `zh-CN`. Ранее созданные кэши других языков не удаляются.
- В game manifest добавлен список официальных локализаций. Для OMORI это английский, японский, корейский и упрощённый китайский: выбранный официальный язык показывает инструкцию использовать настройки игры/Steam, снимает применённый перевод, блокирует все элементы панели кроме выбора языка и не запускает cache/provider-пути. Test Phrase пропускает эти четыре языка; существующие кэши и imported packs сохраняются.
- Явные действия Bulk, Test Phrase, Screen и включение автоматического Screen-перевода теперь сразу запускают выбранный онлайн-провайдер. Story/Full по-прежнему не создают запросов при cache miss.
- Встроенные офлайн-провайдеры удалены из реестра, панели, browser runtime, local helper, launchers, зависимостей и сценариев сборки. Корневая macOS `.app` обновлена; новые релизные ZIP ещё нужно собрать отдельно. Обновление не удаляет уже скачанные данные прежних провайдеров; их по-прежнему удаляет только явный `Reset all data`.
- `Reset all data` теперь является полным factory reset: очищает provider/fuzzy RAM и IndexedDB-кэши, imported packs, историю и логи, оставшиеся файлы прежних провайдеров, API-ключи, настройки, cooldown, сохранённый путь игры и служебные метаданные. Файлы и сохранения OMORI не затрагиваются; после сброса интерфейс просит перезапустить переводчик.
- Совместимый ARM64-runtime на Apple Silicon перед подписью получает `app.icns` из установленной OMORI, поэтому запущенная игра показывает в Dock оригинальный игровой логотип вместо стандартной иконки NW.js.
- Начат безопасный рефакторинг без изменения поведения: повторяющиеся spinner/disabled-состояния кнопок вынесены в тестируемый модуль `runtime-ui.js`, который включается в browser smoke и обе платформенные сборки.
- Подсчёт защищённых слов, сглаженный ETA, исключение времени подготовки провайдера/cooldown и формат строки прогресса вынесены в чистый `runtime-progress.js` с управляемыми часами в unit-тесте; основной runtime сохраняет прежние вызовы и текст интерфейса.
- POST-маршрутизация локального helper физически вынесена из `local_service.py` в отдельный `local_router.py`; декларативный `LocalPostRouter` сохраняет прежние URL, поля запросов, подтверждения и ответы журналов, а оба сборщика упаковывают модуль рядом с helper.
- Вся Shadow DOM-разметка и CSS панели вынесены из основного runtime в тестируемый `runtime-panel.js`; сборка и browser smoke загружают его до controller-кода, а внешний вид и DOM-контракт не изменены.
- Для экономного цикла разработки добавлены компактные `AGENTS.md` и `docs/DEV_MAP.md`, краткий handoff-промт и адресные `test-runtime.sh`/`test-service.sh` с немногословным успешным выводом.
- Удалён скрытый русский словарь имён персонажей: окна имён теперь переводятся только через общий кэш выбранного провайдера и до появления перевода показывают оригинал.
- Добавлен безопасный импорт переводов от других пользователей: приложение потоково определяет игру, язык и provider/model variant, показывает модалку подтверждения и устанавливает выбранный файл отдельным обратимым слоем поверх собственного кэша. Schema 4 не очищает существующие переводы; `Remove imported` возвращает их без потери данных.
- Производительность Google переработана по фактическим логам: общий start-time pacer начинает с 1 секунды, охватывает внутренние retry и адаптивно замедляется до 5 секунд только при системных сбоях. Quality-rejected строки повторяются один раз индивидуально и больше не запускают рекурсивное деление или circuit breaker; бинарный fallback оставлен повреждённым separator/markup. Принятый блок записывается одной IndexedDB-транзакцией и одним helper batch, cache pre-pass использует заранее загруженный набор ключей, а cache-only gameplay не создаёт activity POST. Test Phrase лишён двойной задержки, ETA начинается с первого свежего результата. Обезличенные request stage/size/bytes/latency/outcome сохраняются в `translation-performance.jsonl`, итог Bulk показывает requests и accepted/request.
- После живого прерывания Google Bulk блоки дополнительно ограничены 16 переводимыми protected-text сегментами: 12 насыщенных командами строк больше не раздуваются до 27 маркеров. Рекурсивный fallback возвращает число терминальных systemic-ошибок, поэтому первоначальная структурная ошибка большого блока не включает circuit breaker, если отдельные строки закончились только локальным quality-отказом.
- Адаптивный Google pacer больше не замедляется до пяти секунд по первоначальной структурной ошибке, которую затем обработал fallback. Интервал растёт выше обязательной одной секунды только после полностью терминального systemic-failure блока; это устраняет наблюдавшиеся пятисекундные паузы между успешными HTTP-ответами.
- Живой повторный замер выявил, что одиночные `markup_format_invalid` всё ещё образовывали полный терминальный блок и возвращали задержку к четырём секундам. Separator/markup и quality-коды окончательно исключены из systemic-класса: они сохраняют fallback и локальный `failed`, но pacer и circuit breaker теперь реагируют только на provider/network-сбои.
- Google pacer больше не отправляет свежие запросы с механическим секундным шагом: Bulk, Screen и Test Phrase используют случайный интервал 1,2–1,8 секунды. Адаптивное замедление после настоящих provider/network-сбоев сохраняет тот же разброс поверх повышенной базовой задержки.
- Для OpenAI-compatible добавлен строгий аудит фактического usage без оценок: helper сохраняет provider-reported token counts и cost до проверки результата в обезличенный `openai-compatible-usage.jsonl`, панель агрегирует их по preset/Base URL, а отсутствующие поля показывает как `not reported`. Отклонённый перевод учитывается, если подрядчик успел вернуть usage; невозможность открыть журнал блокирует запрос до отправки, а сбой записи после ответа не запускает платный retry.
- Терминальный Google Bulk больше не отбрасывает одиночную строку после одной повреждённой контекстной сборки: для неё автоматически включается безопасный перевод отдельных видимых сегментов. Quality-retry сразу использует изолированные сегменты вместо повторения того же контекстного запроса. Окончательные отказы записывают точный исходник, код и причину в отдельный локальный `translation-failures.jsonl`; принятый кэш не очищается.
- Живой повторный проход сохранил ещё 522 из 675 строк, но показал 3 400 HTTP-запросов на хвосте: прежний fallback отправлял каждый видимый сегмент отдельно. Google fallback переведён на `/translate_a/t` с отдельным `q` для каждого сегмента и массивом ответа точной длины; команды OMORI остаются локально, один сложный source занимает один paced request. Failure-аудит дополнен фактическим отклонённым кандидатом и конкретной quality-проверкой без ослабления gate.
- Последние протокольные проходы выявили точные edge case хвоста. Пустой перевод отдельного `The` теперь считается допустимым элементом массива и не оставляет лишний пробел между командами; неверная форма batch-ответа один раз откатывается к paced `/single` и не относится к systemic failure. Суммы, AM/PM-время, сгруппированные и длинные числа, одиночные цифры и ordinal `5TH` защищаются локально; punctuation-boundary остаётся частью видимого сегмента и не дублируется в skeleton. Повторённые/неокрашенные ALL CAPS game names, quoted title-case названия и подписи клавиш больше не дают ложный `english_carryover`, тогда как обычные непереведённые фразы остаются запрещены. Для единственного двусмысленного carryover в многочастной строке добавлена финальная slash-context попытка без передачи разметки провайдеру.
- Финальные два markup-отказа разобраны по failure-аудиту: единицы измерения вроде `150mg` теперь защищаются цельным литералом, а сюжетное написание `2geter` нормализуется для Google в `together` и не считается самостоятельным числом. Это устраняет ложные token-layout расхождения, не ослабляя проверку настоящей потери чисел.
- Исправлен cache miss уже готовой Story-реплики, когда `Window_Message` добавляет `<WordWrap>` к исходнику, а Bulk-ассет хранится без него. Fuzzy lookup безопасно переносит только этот runtime-wrapper на перевод; speaker-код и остальные OMORI-команды обязаны совпадать как прежде.
- Любой завершившийся Bulk/Test Phrase сохраняет полноэкранный журнал и итоговый статус без spinner до решения пользователя. После успеха interrupt-кнопка становится зелёной `Finish`; остановленный, вручную прерванный или неполный проход получает `Back to translator`. Фоновые cache-sync статусы не могут перезаписать итог до выхода пользователя.
- Bulk теперь индексирует не только поля `text:`: для `System.HERO` он также извлекает видимые значения `terms` и `plugins`, включая `EQUIP`, `POCKET`, `OPTIONS`, `SNACKS` и `IMPORTANT`. Технические таблицы клавиш, координаты и внутренние message-ссылки не отправляются провайдеру. Версия производного asset index повышена, поэтому следующий явный Bulk безопасно перестроит каталог, переиспользует готовый кэш и запросит только новые строки; Full во время игры остаётся cache-only.
- RPG Maker save-файлы вида `global.rpgsave` теперь защищаются как дословные локальные литералы. Google не получает имя файла как переводимый сегмент, а quality gate не принимает его за непереведённый английский текст; это устраняет два последних ложных `english_carryover` в структурированных строках `System.HERO`.
- Bulk дополнительно расшифровывает безопасный белый список RPG Maker-баз `Actors/Armors/Classes/Enemies/Items/Skills/States/System/Weapons.KEL`. В индекс входят только отображаемые имена, описания, системные terms и сообщения состояний; note-теги, формулы, механические параметры, плагины и события исключены. Для меню экипировки добавляются точные построенные формы `HEART:`, `JUICE:`, `ATTACK:`, `DEFENSE:`, `SPEED:`, `LUCK:` и `HIT:`. Поэтому Full cache-only может переводить характеристики, `SHINY KNIFE` и его описание после следующего явного Bulk.
- `Full Translation` стал рабочим переключаемым режимом и сохраняется как `translationScope: full`; `Story Translation` остаётся значением по умолчанию.
- Full через отдельное сопоставление bitmap-владельцев применяет готовый кэш к целым строкам недиалоговых `Window_Base`-окон: главному меню, предметам, навыкам, экипировке, настройкам, сохранениям, магазинам и боевому интерфейсу.
- Диалоговые `Window_Message`, `Window_NameBox` и `Window_ChoiceList` исключены из общего хука и продолжают использовать стабильные специализированные обработчики. `drawTextEx` защищён от повторного посимвольного перевода.
- Смена Full/Story и Translation/Original перерисовывает активные окна, поэтому оригинальный интерфейс восстанавливается без перезапуска. Отдельные изображения и sprite-bitmap без окна пока не переводятся.
- Full остаётся cache-only во время игры: отсутствующая строка остаётся английской, скрытый запрос провайдеру не выполняется. Cache schema не меняется, стабильный тег `v0.9.43-stable` не затрагивается.
- Добавлен поведенческий тест canvas-режимов; browser smoke проверяет включение Full и сохранение настройки.
- Документация прошла отдельный аудит: синхронизированы английская и русская инструкции, описан cache-only API адаптера и зафиксированы неперехватываемые image/sprite-подписи, динамические cache miss и риск переполнения узких Full-окон.
- Неоднозначный статус `Waiting` при cooldown заменён на `Rate limited by <provider> · retrying in …`, чтобы штатная пауза после `HTTP 429` не выглядела как зависание.
- Кнопка отмены вынесена в отдельную закреплённую строку полноэкранной рабочей области и проверяется по фактическим размерам viewport, поэтому журнал больше не может вытеснить или скрыть её.
- Закреплённая кнопка теперь называется `Interrupt translation (progress will be saved)`, сохраняет вращающийся индикатор и наследует цвет запустившей операции: синий для Bulk или зелёный для Test Phrase.
- Каждый новый Bulk или Test Phrase начинает с чистого живого журнала, поэтому записи прежнего языка, провайдера или модели не смешиваются с текущим проходом; полная сохранённая история остаётся на диске и доступна через `View saved`.
- В живом журнале появился фиксатор `Stop scroll`: он сохраняет текущую видимую строку при поступлении новых записей и разрешает ручную прокрутку, не останавливая перевод; `Resume scroll` немедленно возвращает обычное автоследование за новыми строками.
- Защита разметки переведена на единый сегментный конвейер для всех моделей: OMORI-команды, теги, метаданные и экранированные кавычки больше вообще не отправляются провайдеру. Видимые части получают одну markup-free контекстную попытку с нейтральными разделителями; повреждение разделителя или quality-проверки включает безопасный изолированный fallback. Ответы локально сшиваются с неизменным skeleton перед кэшем.
- Команды говорящих ARTIST `\art` и BERLY `\ber` добавлены в явный OMORI-контракт: они защищены и в prefix-, и в suffix-позиции, а prefix корректно исключается из fuzzy-нормализации исходной реплики.
- Очевидно усечённые, раздутые повторениями или потерявшие значимые литералы ответы получают `translation_quality_invalid`, не попадают в IndexedDB и учитываются Bulk как ошибки с возможностью повторного прохода.
- Cache identity поднята до `omori-markup-v3`, а IndexedDB schema 5 один раз очищает только старый provider-кэш. Импортированные translation packs, сохранения, настройки и ключи остаются на месте.
- MyMemory полностью удалён из реестра провайдеров, общего browser core, интерфейса, тестов и актуальной документации. Его REST URL, UTF-8 splitter и специальные aliases языков больше не входят в приложение.
- После аудита 1 815 свежих Google-записей фильтр исключает подписи этажей `1F`–`5F` и camelCase engine keys `DW …Message`; для кириллических целей quality gate также отклоняет существенные непереведённые английские фрагменты, сохраняя короткие аббревиатуры вроде `DVD`.
- Контекстный Google-путь получил отдельную cache identity `google-context-v1`, поэтому не использует результаты прежнего посегментного прохода. Узкая одноразовая миграция удаляет только старый Google segment-variant выбранного языка и этой игры; другие языки, провайдеры и отдельный imported-pack store не совпадают с предикатом.
- Добавлен третий режим `Screen Translation`: он не извлекает игровые ассеты и только по кнопке `Translate current screen` собирает видимые DOM- и `Window_Base`-строки, использует кэш и переводит оставшиеся строки выбранным провайдером. Автоматические Story/Full-хуки и ожидание между нажатиями остаются cache-only.
- Сообщения Screen разрешают только динамические `\\V`/`\\N`/`\\P`/`\\G`-подстановки, сохраняя в provider input и cache key исходные `<WordWrap>`, `\\mar`, `\\!`, `\\.` и другие защищённые команды. Поэтому строки-шаблоны переводятся с фактически показанными значениями, не теряя переносы, говорящего и управление сообщением. Снимок активных окон очищается при перерисовке, не удерживает старые сцены и не захватывает отдельные sprite-bitmap.
- Короткие свежие canvas-строки одного Screen-снимка объединяются максимум по 12 в защищённый контекстный запрос, тогда как готовые записи по-прежнему читаются индивидуально из RAM/imported-pack cache. Это устраняет десятки последовательных ожиданий Google на экране с множеством однословных подписей, сохраняя общий безопасный pacer; теперь его минимальный случайный интервал составляет 1,2–1,8 секунды.
- `Ctrl+Shift+T` полностью повторяет кнопку `Translate current screen`: запускает Screen-проход, повторным нажатием отменяет его и игнорируется в полях ввода. Комбинация указана прямо на кнопке и в `aria-keyshortcuts`.
- В `Screen Translation` добавлена сохраняемая и выключенная по умолчанию опция `Automatically translate completed dialogue`. После `Window_Message.onEndOfText` она однократно одобряет точную resolved-строку завершившейся страницы и запускает Screen cache/provider-путь; меню остаются ручными, повторная перерисовка не создаёт второй запрос.
- Исправлено самопроизвольное применение старого кэша в Screen mode: новый экран всегда остаётся оригинальным до кнопки/хоткея. Одобрение хранится по конкретному `Window_Base` и точной строке текущей сцены, сохраняется только во время целевой перерисовки результата и снимается при обычном `Bitmap.clear`, `createContents` или смене сцены; DOM auto-pass в Screen отключён.
- Screen-перевод во время паузы `\!` больше не оставляет пустое диалоговое окно: после подстановки перевода message state начинает текущую страницу заново и доходит до той же защищённой команды паузы. Целевая перерисовка Screen теперь обновляет только одобренные текстовые окна, поэтому соседнее окно портрета не очищается.
- Завершённые нестандартные OMORI-окна сообщений (включая журнал заданий), у которых нет обычного `pause`, теперь перерисовываются после прихода Screen-перевода. Состояние паузы сохраняется, а `<WordWrap>` проходит через игровой layout-процессор, поэтому длинный перевод не превращается в обрезанную строку и окно не остаётся пустым.
- Кириллические переводы системных окон рисуются на 8 px меньше штатного размера OMORI, компенсируя визуально более крупные метрики fallback-шрифта. При фактическом переполнении подпись дополнительно уменьшается по доступной ширине, но не ниже 16 px. Размер восстанавливается сразу после конкретной canvas-отрисовки, поэтому соседние строки, диалоги и Original сохраняют штатную типографику.

## Версия 0.9.43 — 2026-08-28 — последний стабильный релиз

- В интерфейсе заложены два режима работы: активный `Story Translation` и отключённый `Full Translation · Coming soon`.
- `Story Translation` сохраняет проверенную границу адаптера: переводятся только диалоговые окна, имена говорящих и варианты ответа. Меню и системные экраны остаются оригинальными ради надёжности и визуальной целостности.
- `Full Translation` пока не имеет обработчика, настройки или runtime-ветки и не может повлиять на текущий кэш или игровой процесс.
- Регрессионные и browser smoke-тесты фиксируют наличие обоих обозначений и техническую недоступность заглушки. Translation cache schema остаётся прежней.

## Версия 0.9.42 — 2026-08-28

- Режим `Super Bulk Translation · 17 languages` полностью удалён: убраны кнопка, список языков, последовательный обработчик, ветки отмены и связанная документация.
- Обычный Bulk одного выбранного языка и `Test Phrase · All Languages` остаются без изменений.
- Translation cache schema не меняется: существующие переводы всех языков, журнал, модели, ключи и сохранения остаются на месте.
- Browser smoke и регрессионные тесты теперь явно проверяют отсутствие Super Bulk в runtime и Shadow DOM.

## Версия 0.9.41 — 2026-08-28

- Интервал последовательных Google-запросов уменьшен с 5 до 1 секунды одновременно для обычного Bulk и Test Phrase.
- Concurrency остаётся равным `1`: запросы не отправляются параллельным burst, а существующий общий `HTTP 429` cooldown 15/30/60 минут продолжает останавливать поток и повторять текущую job.
- Предупреждения интерфейса, тесты и документация синхронизированы с новым интервалом. Translation cache schema не меняется, текущие переводы сохраняются.

## Версия 0.9.40 — 2026-08-28

- ETA обычного Bulk теперь измеряет throughput только по `newlyTranslated` текущего запуска. Cache hit не увеличивает скорость, а лишь исключает уже пройденную job из оставшегося объёма.
- Та же семантика применяется к Super Bulk и Test Phrase: учитываются только новые записи текущей операции (`freshCompleted`/`created`), а не общий `done` с мгновенными попаданиями кэша.
- Прогресс по-прежнему отображается в защищённых текстовых словах; подготовка моделей и cooldown провайдера не входят в измеряемое активное время.
- Добавлена отдельная регрессия, запрещающая возвращение `done/totalJobs` в ETA. Translation cache schema не меняется, пользовательские переводы и текущий проход не затрагиваются.

## Версия 0.9.39 — 2026-08-28

- Удалён ошибочный запрет реплик с `this.`, `/`, `+` и `*`. Решение о пригодности строки теперь принимает общий `hasEnglishText`, поэтому естественные фразы, даты и команды OMORI переводятся, а пути, URL, хэши и числа без текста по-прежнему пропускаются.
- Запись и полная очистка IndexedDB теперь ожидают завершения транзакции. RAM-кэш, счётчики и сообщение об успехе изменяются только после commit; ошибки и abort больше не маскируются.
- macOS-лаунчер отслеживает PID созданного им нативного процесса, а для внешнего запуска сверяет полную команду с выбранной игрой вместо любого одноимённого `nwjs`.
- NW.js 0.115.0 закреплён официальным SHA-256. Повторное использование runtime требует совпавшего verified-marker и успешной проверки подписи; повторная подготовка атомарно заменяет build-bundle без вложенного `nwjs.app`.
- Chromium runtime smoke включён в обычные тесты и обязателен при релизной сборке. Shell-синтаксис теперь проверяется для каждого скрипта отдельно.
- Корневая macOS `.app` заменяется через заранее проверенный staging bundle с rollback-копией, поэтому сборка не оставляет частично скопированное приложение даже при запущенной предыдущей версии.
- Добавлены регрессии по естественной пунктуации OMORI, commit-семантике кэша и hash-locked runtime. Translation cache schema остаётся совместимой; модели, ключи, сохранения и история не удаляются.

## Версия 0.9.38 — 2026-08-28

Сводка изменений промежуточных версий 0.9.24–0.9.38.

### Целостность перевода

- Добавлена общая защита служебной разметки для всех провайдеров: команды OMORI,
  экранированные кавычки, HTML-подобные теги, квадратные метаданные и разделители
  контекста маскируются до перевода и восстанавливаются дословно.
- Реализованы проверка структуры, восстановление значимых пробелов и безопасный
  повторный перевод обычных текстовых сегментов, если модель повредила маркеры.
- Небезопасный результат не записывается в translation cache. Схема кэша поднята
  до `3`/`omori-markup-v2`; миграция 0.9.29 удаляет только несовместимые старые
  переводы, не затрагивая модели, ключи, сохранения и журнал.

### Интерфейс, журнал и обновления

- Во время Bulk, Super Bulk и Test Phrase всё окно занимает рабочая область с
  живым журналом, строкой обработанных слов/ETA/cooldown и кнопкой отмены.
- ETA рассчитывается по скользящей скорости завершённых реплик и не включает
  запуск/установку модели или ожидание ограничения провайдера.
- Новые пары сохраняются в `translation-history.jsonl`; в приложении доступны
  последние 200 записей и экспорт полного JSONL. Очистка живого вида журнал
  сохраняет, а подтверждённый Reset all data удаляет его при factory reset.
- Кнопка Reset all data показывает индикатор выполнения, блокирует повторное
  нажатие до завершения полного удаления и затем просит перезапустить переводчик.
- При старте выполняется проверка manifest обновления. Интерфейс различает
  cache-compatible (`keep`) и требующее пересборки кэша (`rebuild`) обновление,
  показывает до трёх изменений или заглушку и явно сообщает об ошибке проверки.
  Автоматическая загрузка и установка обновления пока не реализованы.

### Производительность и ассеты

- Расшифрованные строки `.HERO` сохраняются в отдельный атомарный
  `omori-asset-index-v1.json` и повторно используются Bulk/Super Bulk.
- Индекс инвалидируется по пути игры, именам, размерам и `mtimeNs` исходных
  файлов; повреждённый либо неполный индекс безопасно перестраивается.
- Asset index считается расходным. Translation cache, модели, ключи, сохранения
  и журнал перевода не являются расходными и не должны удаляться вместе с ним.

### Упаковка и иконка

- macOS-приложение и Windows executable используют оригинальную pixel-art иконку
  OMORI из `app.nw/icon/icon.png`: PNG масштабируется без сглаживания, для macOS
  собирается ICNS, для Windows — ICO с размерами 16–256 px.
- Лицензионные уведомления дополнены пояснением, что иконка и оформление OMORI
  принадлежат OMOCAT и не распространяются как открыто лицензированный код мода.
